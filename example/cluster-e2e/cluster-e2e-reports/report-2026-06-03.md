## 6. 发现的问题(✅ 已修复,见 §8)

### 6.1 cluster 自动 relay:relay publisher 抢 KV 属主锁失败后死锁 stream-list API ⚠️ → ✅ 已修复
- **触发**:在非属主节点(node-2)用 RTSP/RTMP **订阅** 一个他节点拥有的流(`live/camera1`),`ClusterPlugin.OnSubscribe` 自动创建 relay pull-proxy,其 relay publisher 仍走正常 publish 钩子去 Consul 抢 `live/camera1` 的 stream key:
  ```
  subscriber +1  streamPath=live/camera1
  Cluster: acquire stream key failed — kv acquire returned false; live/camera1 may be held by another session
  ```
- **后果**:抢锁失败的 publisher 残留并持有 `Server.Streams` 锁 → `/api/stream/list` 与所有**新订阅**永久 hang(进程其它 API 仍活)。订阅方 ffmpeg 拿不到数据阻塞。
- **根因**:relay publisher 不应去抢属主锁(它不是 origin)。`ClusterRelayDescPrefix` 标记本意防环回,但没能阻止 publish 钩子的 KV acquire。
- **规避**:跨节点录制改用 **distinct streamPath 显式拉流**(`relay/camera1` ← node-1 的 RTSP advertise),不与属主同路径,不抢锁。本报告 Mode (b) 即采用此法,稳定通过。
- **建议**:relay publisher 跳过 KV acquire;或 acquire 失败时 fail-soft 释放 Streams 锁、回收 publisher,避免拖死 stream-list。

### 6.2 pull_proxy_configs 共享 DB 无节点归属 → 重启拉全网(本次已改为本地 sqlite)
- **现象**:最初三节点共享 postgres,`pull_proxy_configs` 表无 node/server 列,32 条 `pull_on_start=t` 全在一张表。**任意节点重启会加载全部 32 条 → 拉全网 32 路 + KV 属主冲突 + 负载激增**。
- **处置**:改为各节点本地 sqlite(§1),pull 配置节点隔离,重启只重拉自己的流。已验证 node-1 `pull/list` 仅 4 路。
- **建议**:若确需共享 DB,pull_proxy_configs 应带节点归属列并按本节点过滤;否则文档应明确 cluster 部署用节点本地 DB。

## 8. 跨节点同名流 KV 冲突死锁 —— 根因与修复(2026-06-03)

用 systematic-debugging 把死锁链定位到代码行,方案 A(m7s 侧定向修),改 3 文件:`plugin/cluster/streamregistry.go` / `index.go` / `streamregistry_test.go`(`relay.go`/`pull_proxy.go` 无净改动)。

### 死锁链(代码级)
1. publisher 经 `plugin.go:681 Server.Streams.Add()` 加入 —— `Streams` 是 `util.Manager`(gotask `Work`,**单 goroutine 事件循环**,`Streams.L==nil` 事件循环模式)。
2. 事件循环 `event_loop.go:154` **内联** `Publisher.Start()`。
3. `publisher.go:152 Server.OnPublish` → cluster `StreamRegistry.OnPublish` → `handleLocalPublish`。
4. `streamregistry.go acquire()` 在事件循环上发**阻塞 Consul `KV().Acquire`** → 撞属主锁返回 `ok=false`。
5. 失败 → 旧 `onStopPublisher` 回调 `Server.Streams.SafeGet`(`manager.go` `m.Call`)**重入同一事件循环**;`job.go:215 Call` 不识别"已在本循环 goroutine",入队 + `<-ctx.Done()` 阻塞 → 循环永远走不到入队回调 → **永久死锁**;此后所有 `stream/list` / 新订阅全挂。

### 三层根因 + 修复
| 根因 | 修复 |
|---|---|
| **RC1** 冲突停流重入 `Server.Streams.SafeGet` 死锁 | `OnPublish` 直接绑定 `pub.Stop` 闭包,**不再 SafeGet 反查** |
| **RC2** 阻塞式 Consul `acquire()` 跑在 Streams 事件循环上 | acquire+冲突停流经 `sr.dispatch`(一次性 `callbackGoTask`)**异步挪到 StreamRegistry 自己的循环** |
| **RC3** relay publisher 误抢 acquire(`PullProxyConfig.Description` 标记丢失:`EnsurePullProxy` 命中已存在 pull-proxy 直接返回、丢弃新 conf 的 `cluster-relay:` 标记) | relay 判据改用 cluster 插件**权威自持的 `activeRelays`**(`isActiveRelay`),Description 仅兜底 |
| **次生** 冲突时 publisher dispose 误 `release` 删掉**属主 peer 的 KV 键** | 加 `acquired` 标志,**只 release 自己真正 acquire 成功的键** |

### 真机回归(对着 3 节点活集群)
- **incident 2(同名显式拉流)**:node-1 用 `live/camera20`(属 node-3)拉流 → `acquire stream key failed` → publisher `unpublish reason="cluster: streamPath already owned by peer"` **干净停止**;node-1 `stream-list` 连续探测全 200/~6ms(**修复前必死锁**);**node-3 仍持有 camera20 属主**(release-guard 生效)。
- **incident 1(订阅触发 auto-relay)**:node-2 订阅 camera1(属 node-1)→ **无 `acquire stream key failed`**;ffmpeg **15s 收到 147 帧**持续供流;relay 生命周期正常(`publish`→服务→`unpublish reason="publish delay close timeout"` 干净 StopOnIdle)。**auto-relay 端到端打通。**
- 单测:`go test -tags cluster ./plugin/cluster/ -count=1` 全绿(新增 offload / release-guard / isActiveRelay 回归守卫)。

### 遗留处置(2026-06-03 续)
- ✅ **音频 mux 0-channels**(commit `5c9eb043`):RTSP 收 G.711(PCMA/PCMU)用空 `codec.PCMACtx{}` → `channels=0` → 录制 mp4 音频轨元数据非法、ffprobe 无法解析整文件。改用 `codec.NewPCMACtx()/NewPCMUCtx()` 默认(mono, 8000Hz, 16bit),仅 SDP 给出 >0 才覆盖。真机验证:node-3 录 camera27 → `channels=1` + 全文件(音频+视频)解码 exit=0。
- ✅ **`EnsurePullProxy` 静默丢字段**:确认"命中已存在就返回、不覆盖"是**正确语义**(不该 clobber 用户配置);relay 标记已由 `activeRelays` 权威解决,无需改行为。仅加非静默 Debug 日志便于排查。
- ✅ **gotask `Call` 同 goroutine 重入(RC4)**(fork `eanfs/gotask` branch `fix/reentrant-call-deadlock`,commit `3b0ee91`):`Job.Call` 在 `Size>0` 时无条件入队 + `<-ctx.Done()` 阻塞,不识别"调用方就是循环 goroutine"→ 重入死锁(util.Manager 的 `SafeGet`/`SafeRange` 在发布钩子里被重入即触发,正是本次 RC1 根因的底层)。修复:新增纯 Go `goID()`(解析 runtime.Stack,无汇编/cgo)+ `EventLoop.loopGID`(run 期记录所在 goroutine)+ `Call` 入队前 `onLoopGoroutine()` 检测重入则内联执行。TDD:`Test_Call_ReentrantFromLoopGoroutine` 无修复 3s 超时死锁 → 有修复 PASS,gotask/m7s 测试无新增回归。**接入 m7s**:fork 临时 `replace` 编译通过 + cluster 测试 green;待发 `gotask v1.0.5`(或加 replace)后 m7s 升级即得根治(届时 m7s 侧 RC1 的 `dispatch` 绕行可保留为防御亦可简化)。
- ℹ️ **auto-relay 首帧延迟 / StopOnIdle**:稳态持续供流已验证(15s/147帧、跨节点 play+record 12MB 2K 录制成功);首个短订阅可能只取尾段属预期。录制音频轨偶见 "non monotonically dts"(时间戳轻微抖动,不影响解析/播放),低优先。
